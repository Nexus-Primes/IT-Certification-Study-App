# Cert Study: notes for Claude Code sessions

An offline study app for IT certifications. Vanilla HTML/CSS/JS front end (ES modules, no build step) plus two ways to run it:

- **Web mode:** `python server.py`, then open http://localhost:8420 (Python standard library only).
- **Windows desktop app:** Electron (`desktop/`), which serves the same `app/` files through a private `app://cert-study` scheme with no open port, and ports the JSON API of `server.py` to Node (`desktop/backend.js`). Installer: electron-builder (NSIS, per user). In-app updates: electron-updater from GitHub Releases.

The front end must behave exactly as before in a browser. Desktop-only UI is feature-detected through `window.certStudyDesktop` (`app/desktop.js`).

## Rules that the tests enforce

- `APP_VERSION` in `app/app.js` equals `CACHE = 'cert-study-vNNN'` in `service-worker.js`, and `package.json` is `NNN.0.0` (run `npm run sync-version`).
- Every file in `app/` and `data/` is listed in the service worker `ASSETS`. `index.html` and `import` lines carry `?v=` numbers: bump them when a file changes.
- Every release has an entry at the top of `app/changelog.js`.
- The service worker is cache-first; a changed file only reaches a browser when `CACHE` changes. (The desktop build does not register a service worker.)
- Keep files LF. Do not hand-edit `data/*.js` (generated by `tools/content/`).
- `server.py` and `desktop/backend.js` must stay equivalent: `desktop/tests/parity.test.js` runs the same requests against both. Change both together.

## Running and testing

```
python server.py                          # web mode
npm install                               # once, for the desktop app
npm start                                 # desktop app from source (your real data folder!)
python tests/run.py static server         # 2 seconds
python tests/run.py                       # full browser suite, about 16 minutes (needs Edge or Chrome)
npm run test:desktop                      # Node tests: backend, parity with server.py, updater, import
node desktop/tests/e2e/smoke.js           # real Electron app on a throwaway data folder
node desktop/tests/e2e/update-feed.js     # real updater against a local fake feed
npm run dist                              # build the installer into release/
```

Tests and rehearsals must never touch real data: the Python suite uses a sandbox copy; the Electron scripts set `CERT_STUDY_DATA_DIR` to a temp folder. Do not edit the project while the long Python run is going (it copies the code at the start).

## Where user data lives (never inside the install or the repo)

- Desktop: `%APPDATA%\Cert Study\` with `data\progress*.json`, `data\profiles.json` (accounts and PIN hash), `backup\`, `files\` (document shelf), `safety-backups\`, `desktop-settings.json`.
- Web mode: next to `server.py` under `data/`, `backup/`, `files/` (all git-ignored).

## Privacy rules

- Never commit, bundle, upload or print `progress*.json`, `profiles.json`, `backup/`, `files/` or any legacy-data folder. `.gitignore` covers them; the installer file list (`package.json` `build.files`) excludes them.
- No personal names, email addresses, tokens or absolute local paths in code, docs, commits or release assets. Commits use the GitHub noreply identity.
- No tokens in the app. The updater uses the public GitHub release feed.
- Ask the owner before anything outward-facing: pushing, creating or publishing a release, changing repo visibility.
